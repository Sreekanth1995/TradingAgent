# Plan: Phase 20 - Plan 02: MultiBrokerManager & Dual-Broker Routing

## Goal
Implement `MultiBrokerManager` to orchestrate parallel order placement, per-account lot multipliers, fail-safe isolation, and account-scoped Redis state across Dhan and Groww.

## Tasks
- [x] Create `broker/manager.py`:
  - `MultiBrokerManager`: Manages active broker clients (`dhan`, `groww`, `flattrade`).
  - Thread-pool parallel dispatch for `place_super_order`, `place_order`, `modify_order`, `cancel_order`, and `kill_switch`.
  - Independent lot multiplier support: `DHAN_LOT_MULTIPLIER`, `GROWW_LOT_MULTIPLIER`, `FLAT_LOT_MULTIPLIER` in `.env` / config.
  - Tagged routing: Support optional `accounts: ["dhan", "groww"]` or `broker: "groww"` tag in payload.
  - Isolated execution: Try/catch per broker account so failures on one broker do not impede or rollback others.
  - Aggregated multi-broker views for `get_positions()`, `get_limits()`, and `get_account_statuses()`.
- [x] Update `server.py`:
  - Initialize `MultiBrokerManager` as the primary broker coordinator while preserving direct `DhanClient` backwards-compatibility.
  - Support multi-account Redis state tracking (`state:dhan:*`, `state:groww:*`).
- [x] Create `tests/test_multi_broker.py`:
  - Test parallel broadcast to both Dhan and Groww.
  - Test account tag override (dispatching to Groww only or Dhan only).
  - Test per-account lot multipliers (e.g. 2 lots on Dhan, 1 lot on Groww).
  - Test fail-safe isolation (Groww failure does not crash Dhan order).
- [x] Run test suite (`pytest tests/test_multi_broker.py`) and verify pass.
